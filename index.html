AI와 함께 개발하는 새로운 작업 방식

“이거 만들어볼까?”라고 말한 뒤,
완성까지 덜 지시하는 개발.

DEVOS는 AI에게 매번 “다음에는 이 파일 수정해”, “테스트도 해”라고 하나씩 시키지 않도록 개발 규칙과 작업 순서를 미리 정리해 주는 도구입니다. 아이디어를 입력하면 필요한 질문을 하고, 준비가 끝난 뒤에만 개발을 시작하도록 도와줍니다.

DEVOS가 왜 필요한가요?

한 줄 요약: AI가 “코드는 빨리 만들지만 프로젝트 전체를 자꾸 잊는 문제”를 줄이기 위해 사용합니다.

AI 코딩 도구는 한 번의 작업은 잘합니다. 하지만 프로젝트가 커지면 “우리가 왜 이렇게 만들기로 했지?”, “지금 어디까지 했지?”, “완료 조건은 뭐였지?”를 놓칠 수 있습니다. DEVOS는 이런 내용을 파일로 남겨 AI가 매번 다시 읽게 합니다.

기존 방식
사람이 계속 지시

“로그인 만들어줘 → 테스트해줘 → 에러 처리해줘 → 문서도 수정해줘”를 반복합니다.

DEVOS 방식
규칙을 먼저 정함

무엇을 만들고, 언제 완료인지, 어떤 구조를 지켜야 하는지 파일로 저장합니다.

목표
명령 횟수 줄이기

사람은 큰 방향을 결정하고, AI는 구현·테스트·수정 과정을 더 길게 맡습니다.

1. 설치하기

목표: 내 PC에서 devos 명령을 사용할 수 있게 만듭니다.

아래에서 운영체제를 선택하거나, 현재 PC에 맞는 파일을 직접 다운로드하면 됩니다.

WindowsPowerShell

Windows 10/11에서 사용합니다.

setup.ps1 다운로드
macOSMacBook / iMac

Apple Silicon과 Intel Mac 모두 사용합니다.

setup-macos.sh 다운로드
LinuxUbuntu · Fedora · Arch 등

일반적인 Linux 개발 환경에서 사용합니다.

setup-linux.sh 다운로드
내 운영체제를 확인하는 중...

설치가 끝났는지 확인하기

터미널에서 아래 명령을 입력합니다.

terminal
devos doctor
✓Git이 설치되어 있는지 확인합니다.
✓Node.js와 npm을 사용할 수 있는지 확인합니다.
✓pnpm과 Codex CLI가 준비되어 있는지 확인합니다.
✓DEVOS 기본 폴더가 만들어졌는지 확인합니다.
처음 설치하는 분: 스크립트가 무엇을 하는지 궁금하면 파일을 메모장/VS Code로 먼저 열어본 뒤 실행해도 됩니다. 공개 저장소이므로 설치 코드를 모두 확인할 수 있습니다.

2. 첫 프로젝트 만들기

예제: “사진과 영상을 날짜별로 기록하는 타임라인 앱”을 만든다고 가정합니다.
1

만들고 싶은 것을 한 문장으로 적습니다.

처음부터 상세한 기획서를 작성할 필요는 없습니다.

terminal
devos new "사진과 영상을 날짜별로 기록하는 타임라인 앱"
2

DEVOS가 필요한 질문을 합니다.

모든 것을 한 번에 묻지 않고, 개발을 시작하려면 꼭 필요한 항목을 채웁니다.

예시 답변
프로젝트 이름: Timeline

어디에서 사용할까요?
> Web + Mobile

주로 사용할 언어는?
> TypeScript

AI가 어디까지 스스로 진행해도 될까요?
> Standard

이 앱을 누가 사용하나요?
> 개인 기록을 남기고 싶은 사용자

첫 버전에서 꼭 필요한 기능은?
> 날짜별 기록, 사진, 영상, 메모, 검색
3

준비가 덜 됐으면 개발을 시작하지 않습니다.

예를 들어 “파일은 어디에 저장할지”가 꼭 필요한데 결정되지 않았다면 먼저 결정하도록 안내합니다.

4

개발에 필요한 문서가 자동으로 만들어집니다.

AI가 다음 세션에서도 기억할 수 있도록 프로젝트 폴더 안에 저장됩니다.

생성되는 문서
project/
├─ AGENTS.md                 # AI가 지켜야 할 규칙
├─ docs/
│  ├─ PRODUCT.md             # 어떤 제품을 만드는지
│  ├─ SPEC.md                # 어떤 기능이 필요한지
│  ├─ ARCHITECTURE.md        # 어떤 구조로 만들지
│  ├─ CAPABILITIES.md        # AI가 사용할 수 있는 기능 목록
│  └─ DEFINITION_OF_DONE.md  # 언제 "완료"라고 볼지
└─ planning/
   ├─ ROADMAP.md             # 큰 개발 순서
   ├─ CURRENT.md             # 지금 하고 있는 일
   └─ DECISIONS.md           # 중요한 결정 기록
5

이제 AI 개발 세션을 시작합니다.

AI는 대화 기억이 아니라 방금 만든 문서를 기준으로 작업합니다.

terminal
cd ~/devos/projects/timeline
devos status
devos codex

3. 어려운 용어를 쉽게 이해하기

처음에는 이것만 기억하면 됩니다: AI가 아무 곳이나 직접 건드리지 않고, 정해진 길을 따라 작업하게 만드는 구조입니다.
AgentAI 개발 작업자입니다. 코드를 읽고 수정하고 테스트하는 역할을 합니다.
ToolAI가 사용할 수 있게 미리 만들어 둔 작은 기능입니다. 예: 할 일 생성, 사용자 조회, 배포 상태 확인.
Capability프로그램이 할 수 있는 “능력” 하나를 뜻합니다. Tool과 거의 같은 맥락으로 이해해도 됩니다.
Service실제 업무 순서를 처리하는 코드입니다. 예: 주문 취소 시 검증하고 환불하고 상태를 바꾸는 흐름.
Core프로그램에서 가장 중요한 규칙입니다. UI나 AI가 바뀌어도 유지되어야 합니다.
CLI터미널에서 명령어로 프로그램 기능을 실행하는 방법입니다. AI가 사용하기에도 좋습니다.
MCP외부 AI가 “이 프로그램에서 어떤 Tool을 사용할 수 있는지” 알아보는 연결 방식입니다.
Worktree같은 Git 프로젝트를 기능별로 별도 폴더에서 동시에 작업할 수 있게 해주는 기능입니다.

4. 프로그램 구조는 이렇게 이해하면 됩니다

예를 들어 사용자가 “할 일 하나 만들어줘”라고 AI에게 말했다고 해보겠습니다.

사용자
AI Agent
create_task Tool
Task Service
DB 저장
중요: AI가 DB에 바로 접근하는 것이 아닙니다. 우리가 미리 만든 create_task라는 안전한 기능을 통해서만 작업하게 합니다.
권장 방향
화면 / CLI / MCP / AI
        ↓
      Tool
        ↓
     Service
        ↓
      Core
        ↓
  Repository / DB

이 구조를 지키면 나중에 Web 화면을 바꾸거나 AI 모델을 바꾸더라도 핵심 업무 규칙을 다시 만들 필요가 줄어듭니다.

5. 프로젝트가 여러 개라면?

원칙: 서로 다른 제품은 폴더와 Git 저장소를 분리하고, 같은 제품 안에서 동시에 작업할 때만 Worktree를 사용합니다.
DEVOS workspace
~/devos/
├─ _control/          # 전체 프로젝트 목록과 공통 규칙
├─ projects/
│  ├─ dreamstore/     # 제품 A
│  ├─ hitgone/        # 제품 B
│  └─ project-c/      # 제품 C
└─ worktrees/
   └─ dreamstore/
      ├─ feat-calendar/     # 캘린더 기능 전용 작업 폴더
      └─ feat-agent-tools/  # AI Tool 기능 전용 작업 폴더

6. AI 역할은 이렇게만 나눠도 충분합니다

역할쉽게 말하면주로 하는 일
Workspace Controller전체 프로젝트 관리자어떤 프로젝트를 먼저 할지 정리
Project Architect프로젝트 설계 담당구조, 큰 기능 순서, 통합 확인
Task Worker실제 코딩 담당기능 구현, 테스트, 수정
처음부터 AI를 10명처럼 나누지 않아도 됩니다. 프로젝트 설계 담당 1개 + 실제 작업 담당 몇 개 정도로 시작하는 것이 관리하기 쉽습니다.

7. 자주 쓰는 DEVOS 명령

명령무슨 뜻인가요?
devos doctor내 PC 개발 환경에 문제가 없는지 확인합니다.
devos initDEVOS 기본 폴더를 처음 만듭니다.
devos new "아이디어"새 프로젝트를 만들기 전에 질문을 받고 준비 상태를 확인합니다.
devos status현재 프로젝트가 어디까지 진행됐는지 확인합니다.
devos worktree new calendar캘린더 기능을 별도 폴더에서 동시에 개발할 준비를 합니다.
devos codex현재 프로젝트/작업 폴더에서 Codex를 시작합니다.

8. AI에게 오래 맡기려면 “완료 조건”이 꼭 필요합니다

사람이 “이 정도면 끝”이라고 판단하는 대신, 검사 결과로 끝을 판단하게 만듭니다.
기능 하나가 끝날 때
바로 확인

관련 테스트를 실행하고 실패하면 다음 작업으로 넘어가지 않습니다.

큰 단계가 끝날 때
전체 확인

빌드, 타입 검사, 린트, 테스트, 구조 검사를 한 번 더 실행합니다.

완료 검사 예시
Build           ✓
Typecheck       ✓
Lint            ✓
Unit Test       ✓
Integration     ✓
Architecture    ✓
Security        ✓

9. AI가 해도 되는 일과 사람이 확인할 일을 나눕니다

작업추천 방식예시
조회AI 자동 처리 가능로그 보기, 사용자 수 확인
일반 수정검증 후 자동 처리 가능할 일 생성, 설정 변경
삭제미리보기 또는 승인데이터 삭제, 프로젝트 archive
비용 발생사람 승인유료 API 호출, 서버 확장
운영 배포사람 승인 권장Production 배포, DB migration
처음에는 안전하게: AI가 코드 작성과 테스트까지는 자동으로 진행하고, 삭제·결제·운영 배포는 사람이 마지막으로 확인하는 방식부터 시작하는 것이 좋습니다.

10. 회사에서 도입한다면 이렇게 시작하세요

1

작은 내부 도구 하나를 고릅니다.

기존 핵심 서비스 전체를 한 번에 바꾸지 않습니다.

2

공통 규칙을 정합니다.

폴더 구조, 완료 조건, 삭제/배포 승인 규칙을 팀 기준으로 정합니다.

3

테스트와 검사를 자동화합니다.

AI가 “완료했다”고 말하는 대신 CI 결과를 기준으로 판단합니다.

4

그 다음에 병렬 AI 작업을 늘립니다.

Worktree와 Task Worker를 추가해 개발량을 늘립니다.

자주 묻는 질문

개발 초보도 쓸 수 있나요?

가능합니다. 다만 Git과 터미널의 아주 기본적인 사용법은 알고 있으면 좋습니다. DEVOS는 복잡한 개발 판단을 줄여주는 도구이지, 프로그래밍 지식 자체를 완전히 없애는 도구는 아닙니다.

Codex만 사용할 수 있나요?

아닙니다. 현재는 Codex 실행 흐름을 우선 지원하지만, 핵심 구조는 특정 AI 모델에 묶이지 않도록 설계합니다.

MCP를 몰라도 되나요?

네. 처음에는 몰라도 됩니다. 먼저 Tool과 CLI를 잘 만드는 것이 더 중요하고, 외부 AI와 연결해야 할 때 MCP를 추가하면 됩니다.

프로젝트를 한 폴더에 전부 넣어도 되나요?

서로 다른 제품이라면 분리하는 것이 좋습니다. 같은 제품의 Web/API/CLI는 하나의 프로젝트 안에서 함께 관리할 수 있습니다.
