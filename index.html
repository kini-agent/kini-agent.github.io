필요한 AI 작업 시스템을 연결합니다.

KINI는 직접 모든 일을 하는 거대한 AI가 아닙니다. 사용자의 요청을 받아 어떤 작업 시스템이 처리할지 정하고 연결해 주는 최상위 CLI입니다. 모두가 같은 깨끗한 KINI Core로 시작하지만, 사용하면서 쌓이는 선호와 규칙은 개인 Profile에 따로 저장되어 사람마다 다른 KINI로 성장합니다.

KINI와 KINI Dev는 뭐가 다른가요?

쉽게 말하면: KINI는 회사의 안내 데스크이고, KINI Dev는 소프트웨어 개발팀입니다.

사용자는 KINI만 기억하면 됩니다. 개발 요청이면 KINI Dev로 보내고, 나중에 데이터·콘텐츠·운영 시스템이 생기면 각각 그쪽으로 연결합니다.

전체 구조
나
↓
KINI
├─ KINI Dev       소프트웨어 개발      ← 지금 사용 가능
├─ KINI Data      데이터 작업          ← 예정
├─ KINI Content   콘텐츠 제작          ← 예정
└─ KINI Ops       서비스 운영          ← 예정
KINI Dev사용 가능앱·웹·서버·CLI 같은 소프트웨어 프로젝트를 준비하고 개발합니다.
KINI Data예정데이터 수집, 정리, 분석, 리포트 작업을 담당할 예정입니다.
KINI Content예정리서치, 글쓰기, 검수, 배포 흐름을 담당할 예정입니다.
KINI Ops예정서비스 운영, 반복 점검, 상태 확인 같은 업무를 담당할 예정입니다.

3. 용어가 어렵다면 이것만 보면 됩니다

KINI사용자의 요청을 받고 어떤 작업 시스템을 사용할지 연결하는 최상위 CLI입니다.
KINI Dev소프트웨어 개발을 담당하는 첫 번째 KINI 시스템입니다.
Agent코드를 읽고 수정하고 테스트하는 AI 작업자입니다.
ToolAI가 아무 곳이나 건드리지 않도록 미리 만들어 둔 작은 기능입니다. 예: 할 일 생성, 사용자 조회.
CLI터미널에서 명령어로 프로그램을 사용하는 방식입니다.
Worktree같은 Git 프로젝트를 별도 폴더로 나눠 여러 기능을 동시에 개발하는 방법입니다.
MCP외부 AI가 프로그램에서 사용할 수 있는 Tool을 알아보고 호출하도록 연결하는 방식입니다. 처음에는 몰라도 됩니다.

6. 같은 KINI를 설치해도, 사람마다 다르게 성장합니다

핵심: KINI Core는 모두에게 같은 깨끗한 기본값으로 유지하고, 개인 취향과 작업 방식은 ~/kini/profile/에만 저장합니다.

예를 들어 어떤 사람은 TypeScript 프로젝트에서 pnpm을 항상 쓰고, 다른 사람은 npm을 선호할 수 있습니다. 이런 차이를 KINI 본체 코드에 넣지 않고 개인 Profile에 저장합니다.

Core와 Profile 분리
KINI Core
공개 GitHub / npm
항상 깨끗한 기본값
        │
        ├──────────────┬──────────────┐
        ↓              ↓              ↓
   사용자 A Profile  사용자 B Profile  사용자 C Profile
        │              │              │
   pnpm 선호        npm 선호        Java 선호
   Expo 우선        Web 우선        Spring 우선
   개인 규칙        개인 규칙        개인 규칙

개인 Profile에는 무엇이 들어가나요?

~/kini/profile
~/kini/profile/
├─ PROFILE.md              Profile 설명
├─ PREFERENCES.md          평소 개발 선호
├─ STACKS.md               자주 쓰는 기술 스택
├─ RULES.md                개인 작업 규칙
└─ systems/
   └─ dev/
      └─ OVERRIDES.md      KINI Dev 전용 개인 규칙
중요: 개인 Profile은 Core의 안전 규칙을 약하게 만들 수 없습니다. 적용 순서는 Core 안전 규칙 → 시스템 규칙 → 프로젝트 규칙 → 개인 Profile입니다.

내 Profile 확인하기

terminal
kini profile show

새 PC로 옮기기

개인 Profile만 별도 폴더로 내보내서 Private Git 저장소나 개인 백업 공간에 보관할 수 있습니다.

내보내기
kini profile export ./my-kini-profile
가져오기
kini profile import ./my-kini-profile

깨끗한 상태로 되돌리기

먼저 무엇이 초기화되는지 확인합니다.

미리보기
kini profile reset --dry-run

실제로 초기화하려면 명시적으로 승인합니다.

실제 초기화
kini profile reset --yes

초기화 전 Profile은 ~/kini/backups/에 자동 백업됩니다. 프로젝트와 KINI Core는 삭제하지 않습니다.

AI는 이 Profile을 어떻게 사용하나요?

kini dev status 또는 kini dev codex를 실행하면 현재 Profile을 프로젝트의 .kini/KINI_PROFILE.md에 자동 동기화합니다. 그래서 같은 KINI Dev라도 사용자별 선호가 실제 Agent 작업에 반영됩니다.

Secret은 Profile에 넣지 마세요. API Key, 비밀번호, 인증 토큰은 Profile 저장 대상이 아닙니다. Secret은 운영체제 Keychain, 환경 변수, Secret Manager 같은 별도 안전한 저장소를 사용해야 합니다.

명령무엇을 하나요?

8. 같은 프로젝트에서 여러 AI를 동시에 쓰고 싶다면

같은 폴더에서 Agent 두 개가 동시에 코드를 수정하면 충돌하기 쉽습니다. 기능별 Worktree를 만들어 각 Agent에게 별도 폴더를 줍니다.

terminal
kini dev worktree new calendar
kini dev worktree new media-upload
kini dev worktree new agent-tools

10. KINI는 여기서 끝나지 않습니다

KINI의 핵심은 DevOS 하나가 아니라 여러 업무 시스템을 같은 방식으로 추가할 수 있는 상위 구조입니다.

예정된 확장 방향
kini dev      소프트웨어 개발
kini data     데이터 수집·분석
kini content  콘텐츠 제작·배포
kini ops      서비스 운영

나중에는:
kini "이번 주 사용자 데이터를 분석해서 보고서 만들어줘"

KINI
  ↓ 요청 분류
KINI Data
  ↓
분석 Agent / Tool

11. npm 배포는 어떻게 연결되나요?

현재: GitHub의 OS별 설치 스크립트로 설치할 수 있고, 패키지 구조는 @kini-agent/kini 이름으로 npm 배포할 수 있게 준비되어 있고, KINI Core 업데이트와 개인 Profile 저장 공간이 분리되어 있습니다.

npm에 공개 배포가 완료되면 Node.js가 이미 있는 개발자는 더 간단하게 시작할 수 있습니다.

npm 배포 후 사용할 형태
npx @kini-agent/kini doctor

# 또는 전역 설치
npm install -g @kini-agent/kini

kini init
kini dev new "앱 하나 만들어볼까?"
주의: 위 npm 명령은 패키지가 npm Registry에 실제 공개된 뒤 사용할 수 있습니다. 현재 문서는 배포 예정 구조를 설명합니다.
